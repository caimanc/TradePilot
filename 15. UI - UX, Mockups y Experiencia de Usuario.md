# 15. UI / UX, Mockups y Experiencia de Usuario

## 15.1 Objetivo de la interfaz

TradePilot debe contar con una interfaz orientada a la **toma de decisiones y supervisión del sistema**, evitando una interfaz saturada de indicadores.

La UI debe permitir al usuario responder rápidamente:

1. ¿Qué está haciendo el mercado?
2. ¿Cuál es la estructura actual?
3. ¿Existe una oportunidad?
4. ¿Qué tan confiable es la señal?
5. ¿Dónde estaría la entrada?
6. ¿Dónde estaría el Stop Loss estructural?
7. ¿Cuál sería el Take Profit?
8. ¿Cuál es el riesgo de la operación?
9. ¿Por qué TradePilot tomó o recomienda esta decisión?
10. ¿Qué está haciendo actualmente una operación abierta?

La interfaz debe priorizar **información accionable sobre información decorativa**.

---

## 15.2 Principios UX

La interfaz debe seguir los siguientes principios:

### Claridad

El usuario debe comprender el estado del sistema en pocos segundos.

No mostrar decenas de indicadores sin contexto. Los indicadores deben utilizarse para construir una interpretación del mercado.

### Jerarquía visual

La información debe organizarse de acuerdo con su importancia:

**Nivel 1 — Decisión**
- BUY / SELL / WAIT
- Estado de la oportunidad
- Probabilidad/confianza
- Estado del mercado

**Nivel 2 — Justificación**
- Estructura
- Tendencia
- Momentum
- Volatilidad
- Confirmaciones

**Nivel 3 — Ejecución**
- Entry
- Stop Loss
- Take Profit
- Distancia SL
- Riesgo
- Volumen

**Nivel 4 — Diagnóstico**
- Indicadores
- Logs
- Datos técnicos
- Estado de módulos

# 15.7 Visualización del Stop Loss

Uno de los elementos más importantes de la UI será mostrar **por qué existe el Stop Loss**.

No debe mostrarse únicamente:

```text
SL = 4378.90
```

Debe poder visualizarse:

```text
                    TP
                    │
                    │
                    │
Entry ──────────────●
                    │
                    │
              Swing Low
              ──────●──────
                    │
                    │
              Buffer
                    │
SL ─────────────────●
```

La interfaz debe comunicar que:

> El Stop Loss se determina principalmente por la estructura y el comportamiento del mercado, mientras que el tamaño de la posición se adapta posteriormente al riesgo permitido.

Esto mantiene separadas las responsabilidades:

```text
Mercado
   ↓
Estructura
   ↓
Swing
   ↓
Stop Loss
   ↓
Distancia SL
   ↓
Position Sizer
   ↓
Volumen
```

El saldo de la cuenta **no debe determinar directamente la distancia del SL**.

# 15.10 Decision Log

TradePilot debe mantener un registro entendible de las decisiones.

Ejemplo:

```text
TIME     EVENT                         VALUE
10:15    Market structure             BULLISH
10:15    Swing High                   4385.20
10:15    Swing Low                    4378.90
10:15    EMA20                        4383.40
10:15    EMA50                        4381.70
10:15    ADX                          33.60
10:15    Signal                       BUY
10:15    SL                           4378.90
10:15    SL validation                VALID
10:15    Risk                         $8.40
10:15    Position size                0.02
```

El log debe permitir reconstruir posteriormente **por qué se tomó una decisión**.

# 15.11 Gráfica interactiva

La gráfica debe ser uno de los elementos principales de la interfaz.

Debe poder visualizar:

- Velas.
- Entry.
- Stop Loss.
- Take Profit.
- Swing High.
- Swing Low.
- Higher High.
- Higher Low.
- Lower High.
- Lower Low.
- Breakout.
- Breakdown.
- Retracement.
- EMA20.
- EMA50.
- EMA200 cuando sea incorporada.
- ATR cuando sea necesario.
- Operaciones ejecutadas.

La gráfica no debe llenarse permanentemente con todos los elementos.

Debe existir un sistema de capas:

```text
☑ Price
☑ Structure
☑ Swings
☑ Entry / SL / TP
☐ EMA20
☐ EMA50
☐ EMA200
☐ ATR
☐ Debug
```

# 15.13 UX para estados de espera

TradePilot no debe mostrar BUY/SELL constantemente.

Cuando no existe una oportunidad válida, la interfaz debe comunicar claramente:

```text
┌───────────────────────────────────────┐
│             WAIT                      │
│                                       │
│ No existe una oportunidad válida.    │
│                                       │
│ Motivos:                              │
│                                       │
│ • Estructura no confirmada            │
│ • Momentum insuficiente               │
│ • R:R inferior al mínimo              │
│                                       │
│ Próxima evaluación: nueva vela        │
└───────────────────────────────────────┘
```

Esto es importante para evitar que el usuario interprete la ausencia de una señal como un error del sistema.

# 15.15 Diseño visual

El diseño debe ser:

- Profesional.
- Sobrio.
- Orientado a trading.
- Alta densidad de información sin saturación.
- Compatible con tema oscuro.
- Legible durante sesiones prolongadas.
- Con estados claramente diferenciados.
- Sin animaciones innecesarias.
- Sin elementos que incentiven decisiones impulsivas.

La interfaz debe evitar una estética excesivamente "gamificada".

La prioridad es:

```text
Información
    >
Comprensión
    >
Decisión
    >
Acción
```

y no:

```text
Animación
    >
Decoración
    >
Acción
```

# 15.16 Arquitectura UX futura

La UI debe diseñarse para consumir información proveniente del dominio y no implementar la lógica de trading.

Conceptualmente:

```text
                 ┌─────────────────────┐
                 │         UI          │
                 └──────────┬──────────┘
                            │
                     View Models
                            │
                 ┌──────────▼──────────┐
                 │ Application Layer   │
                 └──────────┬──────────┘
                            │
                 ┌──────────▼──────────┐
                 │      TradePilot     │
                 │       Core          │
                 └──────────┬──────────┘
                            │
        ┌───────────────────┼────────────────────┐
        │                   │                    │
     Market             Analysis              Risk
        │                   │                    │
     PriceSeries       Structure              SL
     Indicators        Signals                Position
     Swings             Probability           RiskManager
```

La UI **no debe calcular por su cuenta**:

- Stop Loss.
- Take Profit.
- Position Size.
- Risk.
- Probabilidad.
- Señales.

Debe recibir esos resultados desde el motor de TradePilot.

# 15.17 Mockups como referencia, no como implementación final

Los mockups anteriores representan la dirección funcional y UX esperada.

No deben interpretarse como una implementación tecnológica definitiva.

La tecnología de la interfaz podrá definirse posteriormente según la plataforma final seleccionada.

El requisito fundamental es mantener la separación:

```text
UI
 ↓
Application
 ↓
Domain
 ↓
Infrastructure / MT5
```

y evitar que la lógica financiera o de trading termine acoplada a componentes visuales.

# 15.18 Evolución de la UI por fases

La interfaz debe crecer junto con el motor.

### Fase actual

Mostrar:

- Mercado.
- Precio.
- Spread.
- Estructura.
- Swings.
- Indicadores.
- Señal.
- SL estructural.
- Logs.

### Fase Risk Management

Añadir:

- Riesgo.
- Distancia SL.
- Position Size.
- R:R.
- Validación de operación.

### Fase Execution

Añadir:

- Operaciones activas.
- Entry.
- SL.
- TP.
- Estado de ejecución.
- P/L.

### Fase Probabilística

Añadir:

- Confidence Score.
- Factores de decisión.
- Probabilidad estimada.
- Quality Score.
- Historial de setups.

### Fase Machine Learning

Añadir:

- Predicción del modelo.
- Probabilidad ML.
- Features utilizadas.
- Modelo/version.
- Confidence.
- Comparación entre modelo y motor determinista.

La UI debe evolucionar progresivamente y no intentar implementar todo desde el inicio.
